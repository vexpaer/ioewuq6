# SketchUp Campus Repair Benchmark

这个仓库用于测试 Agent 对真实、结构混乱的 SketchUp 校园模型进行修复的能力。

## 任务

输入模型：

`input/6.8.6-颜色微调-1.skp`

目标不是重新设计校园，也不是重新画一个“差不多”的版本，而是在**尽可能保持原模型外观、尺寸、位置、材质和空间关系不变**的前提下，把模型修成结构清晰、几何合理、能够继续编辑的 SketchUp 文件。

重点问题包括：

- 建筑、地面、平台、连桥、山体等几何互相粘连；
- 原始边/面跨越多个语义对象，难以单独选择和编辑；
- 部分面可能未闭合、方向异常或存在多余/错误几何；
- 建筑之间存在复杂平台、连桥与山地拓扑，修复过程中很容易出现平台倾斜、桥断开、建筑错位等破坏。

## 修复要求

1. **保留原始外观**
   - 不改变校园整体视觉布局。
   - 不随意修改建筑形状、尺寸、位置、朝向。
   - 尽量保留原有材质、颜色和可见性。

2. **保留空间与拓扑关系**
   - 连桥仍应连接原本连接的建筑/平台。
   - 平台高度、倾角和连接关系不得因拆分或重组而改变。
   - 山体、道路、地面与建筑之间的原始相对位置必须保持。
   - 不允许为了“修干净”而压平地形、删掉连接结构或移动建筑。

3. **提高模型结构化程度**
   - 将能够明确识别的建筑、平台、连桥、地形等拆分为独立 Group / Component。
   - 避免不同语义对象共享裸几何。
   - 对象应能够被独立选择和编辑。
   - 可采用类似以下的层级，但不强制命名完全一致：

```text
Campus
├── Terrain
├── Platforms
├── Bridges
├── Buildings
│   ├── Building_01
│   ├── Building_02
│   └── ...
├── Roads
└── Other
```

4. **修复明显几何问题**
   - 修复明显错误的破面、漏面、反面、冗余边和异常重叠几何。
   - 不要为了降低边/面数量而删除真实结构。
   - 不确定的几何应优先保留，而不是猜测性重建。

## 禁止事项

- 不得把原模型整体删除后重新近似建模。
- 不得通过大规模删除几何来制造“干净模型”。
- 不得擅自移动、旋转或缩放建筑、平台、桥或地形。
- 不得改变校园设计或增加无关内容。
- 不得只提交截图、报告、OBJ/FBX 等替代格式。

## 交付方式

**必须通过 Pull Request 提交。不要直接修改 main。**

每个 Agent 的 PR 至少必须新增一个可正常打开的修复后 SketchUp 文件：

```text
submissions/<agent-name>/campus_repaired.skp
```

PR 标题：

```text
[Submission] <agent-name> - campus repair
```

PR 正文简要说明：
- 使用的 Agent / 模型；
- 做了哪些主要修复；
- 已知仍未解决的问题（如有）；
- 使用的 SketchUp 版本（如可知）。

除修复后的 `.skp` 外，不强制要求其他交付物。

## 通过标准

提交至少需要满足：

- `.skp` 能正常打开；
- 校园整体外观没有明显改变；
- 建筑、平台、桥和地形没有明显错位；
- 原有关键连接关系仍然成立；
- 模型比原始文件更容易单独选择和编辑；
- 没有通过删除大量正确内容来“修复”。

这是一个 **repair benchmark**，核心评价原则是：

> **在最小破坏原始正确内容的前提下，修复结构和几何问题。**
